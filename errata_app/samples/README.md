# 网页样例与预期结果

两个样例均可在首页一键载入（`samples/sample3x3.csv`、`samples/sample4x4.csv`）。
下列数值均已由自动化测试与手工实测核对。

## 样例一：3×3（`sample3x3.csv`）

OCR 识别表（第 1 行第 1 列 `1300` 系 `1200` 的百位误识，属“一位十进制数字误识”）：

```
1300,340,260
560,780,410
190,620,330
```

原书核准合计（行 1–3、列 1–3）：

| 条目 | 核准值 |
| --- | --- |
| 行 1 合计 | 1800 |
| 行 2 合计 | 1750 |
| 行 3 合计 | 1140 |
| 列 1 合计 | 1950 |
| 列 2 合计 | 1740 |
| 列 3 合计 | 1000 |

发起勘误：目标格 **第 1 行第 1 列**，原值 `1300`，拟改值 `1200`。

预期结果：

- 状态 **证明成立**，最少只需引用 **3 条**合计：行 1=1800、行 2=1750、列 1=1950；
- 满足这 3 条合计的候选原表共 53 张，它们在目标格上全部为 `1200`（无反例）；
- 全份 6 条合计下只剩 1 张可行候选表；
- 系统自动生成凭据，保存原值 `1300`、拟改值 `1200` 与引用合计快照。

对照实验：

1. 只录 行 1=1800、列 1=1950 两条合计再分析 → **存在反例**，页面给出一张同时满足两条
   合计但目标格仍为 `1300` 的候选表，且不生成凭据；
2. 把列 1 合计改成 `1900`（使行和之和 4690 ≠ 列和之和 4640）→ **合计矛盾**，
   原因明确提示行列总和不相等；
3. 凭据生成后，在合计页修改“行 1 合计” → 返回数据集页可见凭据立即变为 **已失效**；
   修改一条未被该凭据引用的合计（如列 3）→ 凭据保持 **有效**。

## 样例二：4×4 上限规模（`sample4x4.csv`）

OCR 表第 1 行第 1 列 `1234`，原书真值为 `1284`（十位 3→8，一位误识）。

核准合计：

| 条目 | 核准值 |
| --- | --- |
| 行 1 合计 | 11652 |
| 行 2 合计 | 15238 |
| 行 3 合计 | 12084 |
| 行 4 合计 | 32838 |
| 列 1 合计 | 14660 |
| 列 2 合计 | 16832 |
| 列 3 合计 | 19054 |
| 列 4 合计 | 21266 |

发起勘误：第 1 行第 1 列，`1234` → `1284`。

预期结果：证明成立，最少引用 **3 条**（行 1=11652、行 2=15238、列 1=14660）；
候选原表共 147,561 张，实测分析耗时约 1.7 秒、进程峰值内存约 180 MB。

## 小规格边界样例（可直接粘贴到首页文本框）

- 1×1，CSV 内容 `500`，录入行合计 `501`、列合计 `501`，拟改 `501`
  → 1 条合计即可证明；
- 1×1，合计录 `10000` → 矛盾（超出每格 0..9999 的上界）；
- 3×3 全 `100` 的表，录入需要四个格各改一位才能满足的合计
  （行合计 500/400/400，列合计 500/400/400）→ 矛盾，原因说明一般整数表可行、
  但超出“至多两格、每格一位数字误识”模型。
